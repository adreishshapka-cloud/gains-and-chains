# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

GAINS & CHAINS — офлайн слот-машина на виртуальные монеты: TypeScript + Pixi.js v8,
упакованная в Electron под Windows. Код, комментарии, документы и коммиты — на русском.

## Команды

```bash
npm run dev          # Vite на http://127.0.0.1:5400 (не 5173 — README здесь устарел)
npm test             # vitest run
npm run build        # tsc --noEmit && vite build
npm run sim          # симулятор, 10 млн раундов
npm run sim:quick    # 200 тыс. раундов — при подкрутке математики
npm run app          # build + electron .
npm run dist         # установщик + portable в ~/gains-build
```

Один тест-файл или один кейс:

```bash
npx vitest run src/core/core.test.ts -t "кулак забирает все цепи на поле"
```

Прогоны симулятора с параметрами:

```bash
npx tsx tools/simulate.ts --spins 1000000 --seed 7 --door FULL_NELSON --buy
```

Скрипты подготовки ассетов требуют Python 3 с Pillow, запускаются из корня:
`prep_background.py фон.png`, `prep_new_assets_1.py`, `prep_bonus_room.py`,
`prep_dungeon_entrance.py`, `prep_screens.py`, `slice_art.py <лист.png>`,
`grid_overlay.py фон.png [шаг]`.

## Архитектура

### Слои

- `src/core/` — мат-модель: ленты, выплаты, линии, фичи, раунд. **Ни одного импорта
  из `game/` или `ui/`.** Иначе симулятор перестанет запускаться без браузера.
- `src/game/` — Pixi: сцена, барабаны, показ выигрыша, маскот, звук, координаты макета.
- `src/ui/` — экраны и кнопки поверх сцены (`DoorScreen`, `PaytableScreen`, `SettingsScreen`,
  `TopUpScreen`, `HotZone` — невидимые кликабельные зоны над нарисованными кнопками).
- `src/state/save.ts` — localStorage: баланс, ставка, статистика, а также накопитель
  жетонов и липкие ♂ (иначе закрытие игры обнуляло бы страховку от сухих полос).
- `electron/main.cjs` — окно без сборки, CommonJS. Навигация наружу и новые окна
  запрещены жёстко; полный экран через IPC `toggle-fullscreen`, а не через браузерный API.

Алиасы `@core/@game/@ui` объявлены в `tsconfig.json` и `vite.config.ts`, но код везде
использует относительные импорты — новый код пишется так же.

### Мост между математикой и графикой: лог событий

Единственная точка сопряжения. `core/round.ts` проигрывает раунд синхронно и
целиком; если ему передан массив `log`, он пишет туда `RoundEvent[]` (`src/core/events.ts`).
`Game.playLog()` читает эту ленту и разыгрывает её во времени. Второго экземпляра
игровой логики не существует — из-за этого отчёты симулятора что-то значат.

Раунд разбит на две фазы, потому что между ними игрок выбирает дверь:

- симулятор ходит через `playRound()` (обе фазы разом);
- игра вызывает `playBase()` → экран выбора двери → `playFree()` → `finishRound()`.

`finishRound()` вызывается ровно один раз в конце и применяет потолок ×5000 —
не дублировать его в игровом слое.

Все выигрыши внутри core — в единицах **общей** ставки (кроме `LineWin.pay`,
он в ставках на линию). В монеты умножает только `Game`.

### Фон — это и есть интерфейс

Рамки, панели, кнопки нарисованы прямо на `src/assets/ui/background.png`. Движок
кладёт поверх только то, что меняется: символы, числа, подсветку. Рисовать панели
кодом поверх макета не нужно.

Отсюда следствие: **`src/game/layout.ts` жёстко привязан к текущему фону.**
Перерисовали фон — накладываем сетку (`python tools/grid_overlay.py фон.png`),
снимаем координаты заново и правим `layout.ts` вместе со списками правок
в `tools/prep_background.py`. Сцена работает в координатах макета 1609×918
один в один, `fitToWindow()` только масштабирует.

Подробности пайплайна ассетов — в [src/assets/ui/README.md](src/assets/ui/README.md)
и [src/assets/symbols/README.md](src/assets/symbols/README.md). Исходные макеты лежат
в папках «новые ассеты …» и «музыка» в корне; коммитятся только результаты обработки.

### Две комнаты и вход в подземелье

`background.png` и `bonus-room.png` — одна раскладка с разной обстановкой:
бонусный фон собран вокруг той же рамки барабанов и той же нижней полосы
(`tools/prep_bonus_room.py`), поэтому `Game.setRoom()` меняет только две текстуры,
фигуру в слоте маскота и тему музыки — координаты не трогает никто. Перерисовали
основной фон — пересоберите бонусный, он берёт рамку из готового файла.

Между выбором двери и первым фриспином играет `DungeonEntrance`: затемнение,
сцена входа, покадровое открытие двери, наезд в проём. Комната подменяется
строго под чёрной шторкой. Это единственное место, которое не слушает
`timing.speed`: на турбо от двух секунд темноты остаётся моргание.

### Экраны-картинки

Правила и настройки — тоже готовые картинки из набора; движок пишет поверх
только живые значения (громкость, ползунок, статистика), запечённые погашены
в `tools/prep_screens.py`. Внутренние координаты этих экранов заданы в системе
картинки и пересчитываются в экранные в самих классах.

Числа правил закреплены `src/ui/rulesArt.test.ts` — он падает, когда мат-модель
разошлась с нарисованным. Правите выплаты, двери, цену покупки — перерисовывайте
картинку и правьте тест.

### Прочее по игровому слою

- Турбо — не ветка кода в каждом файле, а один коэффициент `timing.speed`;
  все паузы идут через `pause()`/`dur()` из `src/game/timing.ts`.
- Отсутствующий файл символа не ломает игру: `placeholders.ts` подставляет цветную
  плитку, поэтому арт можно подкладывать по одному файлу.
- В dev-сборке `window.game` открывает `Game`, у него есть `debugSpin(buy?)`.

## Правила, которые нельзя нарушать (MATH.md §6)

1. Симулятор гоняется **сразу после каждой правки фичи**, а не в конце.
2. Игра и симулятор ходят через одну логику. Раздвоение = отчёты по RTP мертвы.
3. `src/core` не импортирует `game/` и `ui/`.
4. Seed-режим RNG (`createRng(seed)`) сохраняется навсегда — иначе баг раз в
   десять тысяч спинов не воспроизвести.
5. Расхождение RTP игры с симулятором означает баг в игровом слое, а не в математике.

Целевые цифры: RTP 95.88%, поле 5×4, 20 линий, hit 26.3%, бонус раз в 200 спинов,
σ ≈ 15.0, потолок ×5000. Обоснование каждой правки лент и выплат — в [MATH.md](MATH.md).
Концепт и механики — в [DESIGN.md](DESIGN.md), план работ — в [PLAN.md](PLAN.md).

## Ловушки окружения

- **Путь проекта содержит кириллицу.** Распаковщик electron-builder на таком пути
  падает с EPERM, поэтому `npm run dist` идёт через `tools/build-app.mjs` и собирает
  в `~/gains-build`. Прямой вызов `electron-builder` не сработает.
- **Порт 5400, а не 5173.** Windows держит 5145–5244 в зарезервированных под Hyper-V
  диапазонах. Плюс Vite привязан к `127.0.0.1`: по умолчанию он поднимается только
  на IPv6, и запросы на 127.0.0.1 отбиваются.
- `base: './'` в vite.config обязателен — Electron грузит билд через `file://`.
