# Оформление

Файлы здесь собираются скриптом из исходного макета:

```
python tools/prep_background.py фон.png
```

| Файл | Что это |
|---|---|
| `background.png` | Весь интерфейс: комната, рамка барабанов, панели, кнопки |
| `duke-stand.png` | Фигура маскота отдельно, чтобы её можно было анимировать |
| `layout.json` | Размер макета и место фигуры — справочно |

## Почему фон — это весь интерфейс

Рамки, панели и кнопки нарисованы прямо на макете. Движок ничего из этого
не перерисовывает: он кладёт поверх только то, что меняется — символы, числа,
подсветку. Рисовать панели кодом поверх готового макета означало бы положить
худшую копию поверх лучшего оригинала.

Отсюда следует главное: **координаты в `src/game/layout.ts` привязаны к этому
файлу.** Перерисуешь фон — сними позиции заново:

```
python tools/grid_overlay.py фон.png
```

Скрипт положит в `art/` копию с координатной сеткой; по ней правятся числа
в `layout.ts` и список стираемых участков в `prep_background.py`.

## Что скрипт делает с макетом

**Стирает нарисованные значения.** Баланс, ставка, выигрыш, счётчики и числа
в таблице выплат на макете статичны, а в игре меняются. Движок пишет поверх
свои, и старое число просвечивало бы насквозь. Заплатки берутся из краёв самой
области, поэтому на тёмных панелях шва не видно.

**Вырезает маскота.** Не по силуэту, а прямоугольником вместе с куском стены,
с растушёванными краями. Отделить фигуру по цвету не выходит: чёрная кожа
жилетки и тёмные штаны попадают ровно в тот же диапазон, что и стена за спиной,
и любая заливка проходит сквозь фигуру насквозь.

Из этого следует правило для анимации: **масштаб спрайта никогда не опускается
ниже единицы.** Спрайт обязан перекрывать нарисованный на фоне оригинал
целиком, иначе из-под него полезет второй DUKE.
